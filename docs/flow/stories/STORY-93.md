# STORY-93: L3 MVP-2: SYNC artifact creation and ENGAGE gate

## Context
[[STORY-92]] implemented the SYNC-only prompt boundary and ENGINE gate validation, but it is still **agent-instruct only** — the prompt *tells* the agent to write the artifact, but nothing in the filesystem proves SYNC happened until the agent completes a full opencode run. The audit and follow-up review want a **hard, boring, deterministic artifact** that the script auto-generates before any agent runs.

### Remaining gap
The **artifact itself is never auto-generated**. When `--phase sync` runs, the script produces a prompt that tells the agent to write the artifact — but nothing writes it automatically. This means:
1. The artifact format/fields are only in the prompt text, not in a machine-generated template.
2. The agent must format the artifact correctly from scratch.
3. There is no "pending" state — the agent writes the artifact with `status=ready` in one shot, bypassing the review step.
4. No integration test proves an actual file gets written with correct fields.

STORY-93 closes this gap: the script auto-generates a preliminary SYNC artifact (template with deterministic fields filled in), the agent reviews and updates status, and ENGAGE gates on the result.

## Goal
Make `--phase sync` auto-generate a preliminary SYNC artifact into the story file, with deterministic fields (timestamp, git state, dirty count) pre-filled by the bash script. The agent then reviews context and flips the status from `pending` → `ready` (or `blocked`). `--phase engage` already gates on `status=ready`.

## Design

### Artifact location

Same as STORY-92's Captain's Direction: **embedded in the story file** under:

```markdown
## L3 Artifacts

### SYNC

<!-- l3:phase=sync story=STORY-XX status=pending version=1 -->

[auto-generated fields]
...
[agent-reviewed fields]
...

<!-- /l3:phase=sync -->
```

### How it works

1. **Script auto-generates** (new): When `--phase sync` runs, the script writes a preliminary SYNC artifact *into the story file* with `status=pending` and fills in deterministic fields: timestamp, git branch, git head, dirty file count. This is a boring `write_file` / `sed` insertion into the story file.
2. **Prompt instructs agent** (existing): The SYNC prompt already tells the agent to read context and produce a SYNC announcement. The agent finds the auto-generated artifact with `status=pending`.
3. **Agent reviews and updates** (new behavior): The agent changes `status=pending` → `status=ready` (or `blocked`), fills in context summary, readiness note, missing blockers, and "no ACT performed" boundary statement.
4. **ENGAGE gates** (existing): `--phase engage` refuses if no artifact exists or status ≠ `ready`. This already works from STORY-92.

### Artifact format

Auto-generated by the script (deterministic fields):

```markdown
## L3 Artifacts

### SYNC

<!-- l3:phase=sync story=STORY-93 status=pending version=1 -->

Timestamp: 2026-06-16T12:00:00Z
Git branch: prompts
Git head: a1b2c3d
Dirty files: 2

Context Summary:
*(review context above and summarize)*

Readiness: *(write "ready" or "blocked" with reason)*

Missing:
*(list any blockers or write "none")*

Boundary:
- No implementation was performed during SYNC.
- No tests were run during SYNC.
- No commit was made during SYNC.

<!-- /l3:phase=sync -->
```

Fields the script fills automatically:
- `status=` (always `pending` — agent upgrades to `ready`/`blocked`)
- `version=` (always `1`)
- `Timestamp:` — current ISO 8601 datetime
- `Git branch:` — `git branch --show-current`
- `Git head:` — short SHA from `git rev-parse --short HEAD`
- `Dirty files:` — count from `git status --porcelain`
- Boundary boilerplate (always same)

Fields the agent fills during the SYNC session:
- `Context Summary:` — what was read and understood
- `Readiness:` — `ready` or `blocked` + reason
- `Missing:` — blockers or `none`

### Edge cases

- **No story file found for issue**: The script should exit non-zero before attempting write, with a clear error message. This already happens for `--phase engage` (line 121-122 of bootstrap); replicate for `--phase sync`.
- **Artifact already exists**: The script should detect an existing `<!-- l3:phase=sync ... -->` marker in the story file and skip auto-generation, leaving the existing artifact intact. This prevents overwriting an agent-completed artifact on re-run.
- **Story file has no `## L3 Artifacts` section**: The script should insert the section + artifact at end of file.
- **Dirty repo**: No impact — artifact records the dirty count as-is.
- **Detached HEAD**: Use `git rev-parse --short HEAD` (already works detached).
- **Race condition / concurrent writes**: Not a concern at this stage — ADLAI is single-user.

### Script changes required

In `session_bootstrap.sh`, within the `if [[ "$PHASE" == "sync" ]]` branch, BEFORE emitting the prompt:

1. Validate story file exists (exit 1 with error if not found — mirror ENGAGE logic).
2. Check for existing `<!-- l3:phase=sync` in story file. If found, skip auto-generation (leave existing artifact intact).
3. Detect or insert `## L3 Artifacts` section heading in the story file.
4. Insert the artifact block under `### SYNC` with deterministic fields filled.
5. Update the ARTIFACT TARGET section in the prompt to note the auto-generated artifact exists and needs review.

### Prompt change

The SYNC prompt currently says "Your SYNC artifact must be written to: ..." After auto-generation, the tone changes to:

> A preliminary SYNC artifact has been auto-generated in `[path]` with `status=pending`.
> Review the context above, then update the artifact:
> - Change `status=pending` → `status=ready` (or `blocked`)
> - Fill in Context Summary, Readiness, and Missing fields
> - Do NOT modify the auto-generated fields (timestamp, branch, head, dirty count, boundary boilerplate)

## Notes
- Keep the artifact story-bound and grep-able.
- Prefer a boring, deterministic format over a general runner.
- Do not wire qwen/opencode execution yet.
- Auto-generation is a `sed`/`awk`/`printf` operation in bash — no Python needed.
- The `status=pending` → `status=ready` transition is the agent's job, not the script's. The script only sets `pending`.
- After this story, L3 is fully built for the SYNC→ENGAGE boundary. Only ACT and WRAP phases remain gated.
