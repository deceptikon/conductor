# STORY-99: Pult Phase 3 — Absorption (Deprecate Bash Bootstrap)

## Context

[[STORY-95]] and [[STORY-96]] build the Python wrapper and artifact injector.
[[STORY-97]] hardens the bash script's prompt gates. [[STORY-98]] proves E2E tests
pass against the real vault.

The final step is full absorption: move the prompt-generation logic from
`session_bootstrap.sh` (bash) into `pult.py` (Python), making the bash script
a thin compatibility shim (or removing it entirely). This eliminates:
- The bash path-resolution fragility (replaced by `paths.py`)
- The partial stderr capture (replaced by `ErrorClassifier`)
- The manual `printf` heredoc approach (replaced by Python Jinja2 or f-string templates)

This is P2 because the system is already functional and safe after [[STORY-94]]
through [[STORY-98]]. Absorption is an optimization for maintainability, not a
critical bug fix.

## Goal

Port the prompt-generation logic of `session_bootstrap.sh` into
`backend/app/services/pult.py`, specifically into a `PromptBuilder` class.
The bash script becomes a one-liner that calls `pult`:

```bash
#!/bin/bash
# session_bootstrap.sh — compatibility shim
python -m backend.app.services.pult run "$@"
```

Or it is removed entirely and callers are updated to use `pult` directly.

## Acceptance Criteria

- [ ] `PromptBuilder` class exists in `pult.py` with methods:
  - `build(story_id: str, phase: str) -> str` — generates the full phase prompt
  - Reads `STATE.json`, issue content (via `rvc`), linked specs (via `rvc context`), `DECISIONS.md`, `GOTCHAS.md`, git state
  - Applies the **restructured prompt order** from [[STORY-97]]: phase instruction first, context payload second
  - Handles all 4 phases: `sync`, `engage`, `act`, `wrap`
- [ ] `Pult.run()` uses `PromptBuilder` internally instead of calling `session_bootstrap.sh`
- [ ] `session_bootstrap.sh` is either:
  - (Option A) Reduced to a one-liner shim calling `pult`, OR
  - (Option B) Removed with a deprecation note in the commit message
  - **Decision to be made in ENGAGE phase based on conductor dependency audit**
- [ ] All 4 phase prompts generated by `PromptBuilder` are byte-for-byte equivalent (or functionally equivalent) to those previously generated by the bash script
- [ ] E2E flow tests from [[STORY-98]] pass against the `PromptBuilder` implementation (no bash involved)
- [ ] Unit tests in `backend/tests/unit/test_prompt_builder.py` cover:
  - SYNC prompt: phase header in first 5 lines
  - ENGAGE prompt: gate validation content present
  - ACT prompt: QA command (`uv run pytest`) present
  - WRAP prompt: code-mutation HARD STOP in first 5 lines
  - All phases: issue content is included
  - All phases: decisions and gotchas are included
- [ ] `uv run pytest backend/tests/unit/test_prompt_builder.py -q` exits 0
- [ ] `uv run pytest backend/tests/integration/test_flow_real_vault.py -v` exits 0 (E2E still green)
- [ ] No bash subprocess call remains in `Pult.run()` (bash shim is only allowed in `session_bootstrap.sh` itself)
- [ ] `ruff check backend/app/services/pult.py` clean

## Implementation Notes

`PromptBuilder` reads from the real filesystem and calls `rvc` via subprocess
(for issue and context content). The DECISIONS/GOTCHAS reading and git state
collection move from bash `awk`/`grep` to Python equivalents.

The `rvc` subprocess call is unavoidable (it is the canonical interface to the
vault). It is isolated in `PromptBuilder._get_issue()` and `PromptBuilder._get_specs()`
methods, making it mockable in unit tests.

```python
class PromptBuilder:
    def _get_issue(self, story_id: str) -> str: ...      # rvc issue STORY-XX
    def _get_specs(self, story_id: str) -> str: ...      # rvc context STORY-XX
    def _get_decisions(self) -> str: ...                  # reads DECISIONS.md
    def _get_gotchas(self) -> str: ...                    # reads GOTCHAS.md
    def _get_git_state(self) -> dict: ...                 # git branch, status, log
    def build(self, story_id: str, phase: str) -> str: ...
```
