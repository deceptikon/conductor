# STORY-99: Pult Phase 3 — Absorption (Deprecate Bash Bootstrap)

## Context

[[STORY-95]] built `pult gather` + `pult validate`.
[[STORY-96]] built `pult inject` + `pult publish`.
[[STORY-97]] built `pult prompt` with restructured HARD STOP order.
[[STORY-98]] proved E2E tests pass against the real vault.

The final step is full absorption: `session_bootstrap.sh` is replaced by the
**pult subcommand chain**:

```bash
# Old (monolithic):
bash session_bootstrap.sh --phase sync STORY-87

# New (staged):
pult gather STORY-87 \
  && pult validate STORY-87 --phase sync \
  && pult inject STORY-87 --phase sync \
  && pult prompt STORY-87 --phase sync
```

This eliminates:
- The bash path-resolution fragility (replaced by `paths.py`)
- The partial stderr capture (replaced by `ErrorClassifier`)
- The manual `printf` heredoc approach (replaced by Python f-string templates)
- The untestable monolith (replaced by 4 independently testable subcommands)

This is P2 because the system is already functional and safe after [[STORY-94]]
through [[STORY-98]]. Absorption is an optimization for maintainability, not a
critical bug fix.

## Goal

Make `pult` the canonical entry point for all L5 (bootstrap) operations.
`session_bootstrap.sh` becomes a thin compatibility shim that calls the pult
subcommands in sequence, or is removed entirely.

- [ ] `pult` is the canonical CLI for all L5 operations:

  - `pult prompt <story_id> --phase <phase>` — prompt assembly

- [ ] `session_bootstrap.sh` is either:
  - (Option A) Reduced to a one-liner shim: `python -m backend.app.services.pult "$@"`, OR

- [ ] All 4 phase prompts generated by `pult prompt` are byte-for-byte equivalent (or functionally equivalent) to those previously generated by the bash script

- [ ] **Ensure pult_node is fully wired and operational in conductor pipeline**, replacing bash bootstrap as the L5 entry point

- [ ] **G6 gate:** `pult gather` verifies it reads canonical spec copies from `TEAMFLOW/20_Specs/` (not stale duplicates in ADLAI vault); logs warning if duplicate detected
- [ ] Unit tests cover all pult subcommands:
  - `test_pult_gather.py` — context collection
  - `test_pult_validate.py` — gate validation

- [ ] `uv run pytest backend/tests/integration/test_flow_real_vault.py -v` exits 0 (E2E still green)
- [ ] No bash subprocess call remains in any pult subcommand (bash shim is only allowed in `session_bootstrap.sh` itself)
- [ ] `ruff check backend/app/services/pult.py` clean

## Edge Cases & Error Scenarios

| Scenario | Expected Behaviour |
|----------|-------------------|
| `session_bootstrap.sh` is deleted but a legacy script still calls it | `Pult.run()` is the canonical entry point; legacy callers updated or shim provided |
| `PromptBuilder` generates prompt that differs from bash by whitespace only | Functionally equivalent: same sections, same ordering, same content (whitespace normalization acceptable) |
| `rvc` is unavailable during absorption testing | G2.5 degradation: test continues with placeholder issue text; test logs warning |
| Git repo has no commits (empty repo) | `PromptBuilder` handles gracefully: git state section shows "(no commits)" |
| `DECISIONS.md` or `GOTCHAS.md` do not exist | `PromptBuilder` omits the section without error |
| Conductor calls `pult_node` but pult is not installed | Conductor routing fails with clear error; pipeline does not silently skip |

## Non-Functional Requirements

- **Performance:** `PromptBuilder.build()` must complete in <2s (dominated by rvc/git subprocess calls)
- **Maintainability:** All prompt templates are Python f-strings or Jinja2 templates (not bash heredocs)
- **Testability:** Every `PromptBuilder` method is independently unit-testable (rvc/git calls are mockable)
- **Observability:** `PromptBuilder` logs the size of each prompt section (contract, issue, specs, decisions, gotchas, git) for debugging bloat

## Implementation Notes

The pult subcommands are implemented as methods on the `Pult` class, with each
subcommand registered via `argparse` subparsers:

```python
# pult.py CLI structure
parser = argparse.ArgumentParser(prog="pult")
sub = parser.add_subparsers(dest="cmd")

# pult gather <story_id>
gather_p = sub.add_parser("gather")
gather_p.add_argument("story_id")

# pult validate <story_id> --phase <phase>
validate_p = sub.add_parser("validate")
validate_p.add_argument("story_id")
validate_p.add_argument("--phase", required=True)

# pult inject <story_id> --phase <phase>
inject_p = sub.add_parser("inject")
inject_p.add_argument("story_id")
inject_p.add_argument("--phase", required=True)

# pult prompt <story_id> --phase <phase>
prompt_p = sub.add_parser("prompt")
prompt_p.add_argument("story_id")
prompt_p.add_argument("--phase", required=True)

# pult publish <story_id>
publish_p = sub.add_parser("publish")
publish_p.add_argument("story_id")
```

Each subcommand is independently testable. The `rvc` subprocess call is isolated
in `Pult._get_issue()` and `Pult._get_specs()`, making it mockable in unit tests.
